# YTM Player — власний плеєр для твоїх плейлистів YouTube Music

Мінімальний прототип: Node.js/Express backend (обгортка над неофіційним пакетом
`ytmusic-api`) + React (Vite) frontend, який відтворює трек за треком через
офіційний YouTube IFrame Player API.

## Структура

```
ytm-player/
  server/   # Express API: /api/playlist/:id, /api/search
  client/   # React UI + плеєр
```

## Швидкий старт

### 1. Backend

```bash
cd server
npm install
cp .env.example .env
npm start
```

Сервер підніметься на `http://localhost:4000`.

### 2. Frontend

```bash
cd client
npm install
npm run dev
```

Відкрий адресу, яку виведе Vite (типово `http://localhost:5173`).

## Як знайти ID плейлиста

Відкрий свій плейлист на `music.youtube.com`, подивись на URL:

```
https://music.youtube.com/playlist?list=PLxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
                                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ це ID
```

Встав цей ID у поле в застосунку.

## Приватні плейлисти (потрібен cookie)

`ytmusic-api` без авторизації бачить лише публічні/непублічні-за-посиланням
плейлисти. Щоб працювати з приватними колекціями свого акаунта:

1. Залогінься на `music.youtube.com` у браузері.
2. Відкрий DevTools (F12) → вкладка Network.
3. Онови сторінку або відкрий будь-який плейлист, знайди запит до
   `.../youtubei/v1/browse`.
4. У заголовках запиту (Request Headers) скопіюй значення `Cookie`.
5. Встав його у `server/.env` як `YTM_COOKIE=...`.

⚠️ Це emulate-запити веб-клієнта, а не офіційний API Google — так само, як і
Python-бібліотека `ytmusicapi`. Це працює стабільно для особистого використання,
але:
- Google може змінити внутрішній формат запитів — тоді пакет доведеться оновити.
- Формально це не офіційно підтримуваний спосіб доступу — не варто
  ділитись своїм cookie з кимось чи використовувати це в публічному
  комерційному продукті.

## Список "усіх моїх плейлистів" (get_library_playlists)

Пакет `ytmusic-api` (npm) не вміє віддавати повний список бібліотечних
плейлистів. Замість того щоб вручну відтворювати їхній внутрішній
browse-запит до YouTube Music (структура відповіді складна і змінюється з
часом), у проєкті є маленький **Python-мікросервіс** (`python-service/`), який
використовує перевірений метод `ytmusicapi.get_library_playlists()`. Node-бекенд
просто проксує запит до нього.

### Налаштування python-service

```bash
cd python-service
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Одноразова авторизація — відкриє браузер, попросить залогінитись у Google,
# і збереже токен у oauth.json поряд зі скриптом.
ytmusicapi oauth

python app.py                   # сервіс піднімається на http://localhost:5000
```

`ytmusicapi oauth` — офіційно підтримуваний бібліотекою спосіб авторизації
(через OAuth, без ручного витягування cookie з DevTools). Якщо він у тебе не
спрацює (Google іноді обмежує цей флоу для деяких типів застосунків), у
документації `ytmusicapi` є альтернативний спосіб через браузерні заголовки —
докладніше на https://ytmusicapi.readthedocs.io/en/stable/setup/index.html

### Як це підключається

1. Піднімаєш `python-service` (порт 5000).
2. Піднімаєш `server` (Node, порт 4000) — він знає про Python-сервіс через
   змінну `PYTHON_SERVICE_URL` (типово вже `http://localhost:5000`, окремо
   налаштовувати не треба).
3. У фронтенді з'явилась кнопка "📚 Мої плейлисти" — тисни, і вона підтягне
   реальний список твоїх колекцій з YouTube Music, а клік по назві одразу
   завантажить трек-лист і почне грати.

### Альтернатива без Python

Якщо не хочеш тримати два бекенди — просто зберігай кілька улюблених
playlist ID (скопійованих з URL) у конфіг-файлі на фронтенді й вибирай з
випадаючого списку замість динамічного запиту "дай усі мої плейлисти". Це
покриває 90% реального use-case (у тебе ж, ймовірно, не сотні активних
колекцій) і не потребує Python узагалі.

## Відтворення

Трек грається через офіційний вбудований YouTube-плеєр (IFrame Player API) —
маленьке відео 356×200 на сторінці. Це легальний спосіб відтворення (на
відміну від прямого вилучення аудіопотоку). Коли трек закінчується — плеєр
автоматично перемикається на наступний у твоїй черзі.

Керування чергою: кнопки ⏮/⏭, "Перемішати", та стрілки ↑/↓ біля кожного
треку, щоб вручну змінити порядок відтворення.

## Наступні кроки (ідеї для розвитку)

- Зберігати список улюблених playlist ID (і власний порядок треків) у
  localStorage або невеликій БД (SQLite), щоб не вводити ID щоразу.
- Drag-and-drop для зміни порядку замість кнопок ↑/↓.
- Режим "черга з кількох плейлистів підряд".
- Приховати відео-плеєр і показувати лише аудіо-контроли (тільки CSS,
  сам плеєр однаково вантажить відео).
